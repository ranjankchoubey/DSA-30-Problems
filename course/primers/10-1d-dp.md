## What is dynamic programming

**Dynamic programming (DP)** solves a problem by combining answers to **smaller versions of the same problem**, computing each smaller answer **once**.

It applies when both of these hold:

- **Optimal substructure:** the answer for size `i` can be built from answers for smaller sizes.
- **Overlapping sub-problems:** a plain recursive solution would compute the same smaller answers again and again.

Example: Climbing Stairs (1 or 2 steps at a time). `ways(5) = ways(4) + ways(3)`, and `ways(4) = ways(3) + ways(2)`, so `ways(3)` is needed twice, `ways(2)` three times, and so on. Plain recursion is O(2ⁿ); computing each value once is O(n).

| Style | How | Pros | Cons |
| --- | --- | --- | --- |
| **Top-down** (memoisation) | Write the recursion, cache results | Closest to the recurrence; only computes needed states | Recursion depth limit (~1000 in Python); call overhead |
| **Bottom-up** (tabulation) | Fill a table from the base cases upwards | No recursion; easy to shrink memory | You must pick the fill order yourself |

```python
from functools import cache

@cache                          # top-down: each ways(i) is computed once
def ways(i):
    if i <= 1:
        return 1
    return ways(i - 1) + ways(i - 2)


def ways_bottom_up(n):          # bottom-up, keeping only the last two values
    two_back, one_back = 1, 1
    for _ in range(2, n + 1):
        two_back, one_back = one_back, one_back + two_back
    return one_back
```

## State and recurrence

Every DP solution answers the same five questions. Write them down before coding.

| Question | Climbing Stairs | Maximum Subarray |
| --- | --- | --- |
| 1. **State:** what does `dp[i]` mean? | ways to reach step `i` | best sum of a subarray **ending at** `i` |
| 2. **Recurrence:** how is `dp[i]` built from smaller states? | `dp[i−1] + dp[i−2]` (last move was 1 or 2) | `max(nums[i], dp[i−1] + nums[i])` |
| 3. **Base cases** | `dp[0] = dp[1] = 1` | `dp[0] = nums[0]` |
| 4. **Order** | `i` increasing | `i` increasing |
| 5. **Answer** | `dp[n]` | `max(dp)` |

Tips:

- **Think about the last step.** "How did I get to `i`?" usually gives the recurrence.
- **"Ending at `i`" states** are the standard trick for subarray problems. "Best subarray anywhere" is hard to extend; "best subarray that ends exactly here" is easy, and the overall answer is the max over all `i`.
- **Shrink memory:** if `dp[i]` only reads `dp[i−1]` and `dp[i−2]`, keep two variables instead of a list. Update them together (`a, b = b, a + b`).

## Kadane

Kadane's algorithm is the "ending at `i`" state for the **maximum subarray sum**:

```python
def kadane(nums):
    best = current = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)       # start fresh at x, or extend
        best = max(best, current)
    return best
```

**Time:** O(n) · **Space:** O(1)

Extend the previous subarray only if it helps, which for sums means "if it's positive". Start `best` at `nums[0]`, not 0, so an all-negative array returns its largest element.

## Tracking max and min

For **products**, a negative number flips the order: the largest product becomes the most negative and vice versa. So keep **two** "ending at `i`" states, the largest and the smallest:

```python
def max_product(nums):
    best = cur_max = cur_min = nums[0]
    for x in nums[1:]:
        candidates = (x, x * cur_max, x * cur_min)
        cur_max, cur_min = max(candidates), min(candidates)
        best = max(best, cur_max)
    return best
```

- A **negative** `x` turns `cur_min` into the new `cur_max`.
- A **zero** makes both states 0. At the next element, `x` alone wins, so the subarray restarts.
- The same "two states that swap" idea counts lengths in Maximum Length of Subarray With Positive Product (`pos` and `neg`).

## Expand around centre

Not table-based DP, but the standard tool for palindromic **substrings**. Every palindrome has a centre: a character (odd length) or a gap between two characters (even length), `2n − 1` centres in total. Expand outwards while the ends match:

```python
def expand(s, left, right):
    while left >= 0 and right < len(s) and s[left] == s[right]:
        left -= 1
        right += 1
    return left + 1, right - 1              # bounds of the palindrome found

def longest_palindrome(s):
    best = (0, 0)
    for c in range(len(s)):
        for lo, hi in (expand(s, c, c), expand(s, c, c + 1)):
            if hi - lo > best[1] - best[0]:
                best = (lo, hi)
    return s[best[0]:best[1] + 1]
```

**Time:** O(n²) · **Space:** O(1)

## Table over substrings

The DP view of palindromes: `dp[i][j]` = "is `s[i..j]` a palindrome?"

```
dp[i][j] = s[i] == s[j] and (j - i < 2 or dp[i+1][j-1])
```

`dp[i][j]` reads `dp[i+1][j−1]`, a cell with a bigger `i`, so fill `i` from `n − 1` **down** to 0. This is O(n²) time and O(n²) space. Expanding around centres visits the same `True` cells without storing them, which is why the expansion method is preferred.

**General lesson:** for a 2-D table, find which cells each cell reads, and choose a loop order that computes those first.

## How to recognise the pattern

| You see… | Think… |
| --- | --- |
| "how many ways to reach / build …" | DP, count by the last step |
| "minimum / maximum cost to reach …", choices at each step | DP over positions |
| "maximum sum subarray", contiguous | Kadane |
| "maximum product subarray", negatives and zeros | Kadane with max **and** min |
| "longest / count palindromic substrings" | expand around centre (or `dp[i][j]`) |
| a recursive solution that repeats the same calls | add `@cache`, then convert to bottom-up |

## Common pitfalls

- Writing code before stating what `dp[i]` **means**. Most DP bugs are an unclear state.
- Wrong base cases, e.g. starting a max at 0 when every value can be negative.
- Updating two rolling variables one at a time, so the second update reads the new value.
- Keeping only the max in a product problem; a negative number needs the min.
- Forgetting even-length centres when expanding palindromes.
- Filling a 2-D table in an order that reads cells not yet computed.
- Top-down recursion deeper than ~1000 levels hits Python's recursion limit.
